# Автоматическая выгрузка уведомлений BIDV из Яндекс Почты

Скрипт запускается GitHub Actions раз в час, читает новые письма от одного заданного отправителя по IMAP, распознаёт только три подтверждённых шаблона BIDV и выгружает на Google Drive отдельный JSON на каждую операцию.

В JSON попадают только `transaction_type`, `amount_vnd`, `recipient_type`, `recipient_name`, `transaction_at` и `reference_number`. Скрипт намеренно не сохраняет номер счёта или карты, IP-адрес, операционную систему, полный текст письма и комментарий к переводу.

## Поддерживаемые операции

Поддерживаются `QR Pay` с полем `Merchant Name`, а также внутренние и межбанковские переводы с полем `Beneficiary name`. Для перевода имя — это получатель, а не гарантированно мерчант.

Каждая операция выглядит так:

```json
{
  "transaction_type": "qr_pay",
  "amount_vnd": 135000,
  "recipient_type": "merchant",
  "recipient_name": "VIETTEL TELECOM",
  "transaction_at": "2026-09-13T11:00:14",
  "reference_number": "0551bXq4-8C58VQ1DA"
}
```

Если письмо отличается от известных шаблонов, оно не выгружается, а задача заканчивается успешно с предупреждением в логе. Это исключает выгрузку некорректных данных.

## Первичная настройка

### 1. Подготовьте Яндекс Почту

В настройках Яндекс Почты включите доступ к почтовому ящику по IMAP. Создайте пароль приложения для почтовых программ и сохраните его: это отдельный пароль, а не пароль от ящика. Не передавайте его в чат и не записывайте в репозиторий.

### 2. Подготовьте папку Google Drive и сервисный аккаунт

Создайте отдельную папку на Google Drive, куда будут попадать JSON-файлы. Скопируйте идентификатор папки из URL: в адресе `https://drive.google.com/drive/folders/ID_ПАПКИ` нужен фрагмент после `folders/`.

В Google Cloud Console создайте проект, включите **Google Drive API**, затем создайте сервисный аккаунт и ключ типа JSON. Откройте доступ к созданной папке Drive для e-mail сервисного аккаунта с правом **Редактор**. E-mail виден в JSON-ключе в поле `client_email`.

Сервисный аккаунт не получает доступ ко всему вашему Google Drive, только к папке, которой с ним поделились.

### 3. Создайте приватный репозиторий GitHub

Создайте новый приватный репозиторий и загрузите туда все файлы из этой папки. Не коммитьте JSON-ключ Google или пароль Яндекс Почты.

В репозитории откройте **Settings → Secrets and variables → Actions** и добавьте следующие **Repository secrets**:

| Имя | Значение |
| --- | --- |
| `YANDEX_EMAIL` | Полный адрес ящика Яндекс Почты |
| `YANDEX_APP_PASSWORD` | Пароль приложения Яндекс Почты для IMAP |
| `MAIL_SENDER` | Точный e-mail отправителя уведомлений BIDV |
| `GOOGLE_DRIVE_FOLDER_ID` | Идентификатор папки на Google Drive |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Полное содержимое JSON-ключа сервисного аккаунта |

Если GitHub не принимает многострочный JSON-ключ, закодируйте файл локально в Base64 и положите в секрет получившуюся одну строку. Скрипт понимает оба варианта:

```bash
base64 -w 0 service-account.json
```

Необязательная переменная репозитория `YANDEX_MAIL_FOLDER` задаёт папку Яндекс Почты; по умолчанию используется `INBOX`. Для папки с кириллицей укажите её точное имя, как оно отображается в Яндекс Почте.

### 4. Проверьте вручную

Откройте вкладку **Actions**, выберите workflow «Выгрузка уведомлений BIDV» и нажмите **Run workflow**. После первого успешного запуска GitHub автоматически добавит в репозиторий файл `processed_uids.json`; там только технические UID уже проверенных писем, без текста, сумм и реквизитов.

JSON-файл получает имя `bidv-<reference_number>.json`. Повторный запуск не создаст дубликат: скрипт проверяет и локальный журнал UID, и наличие файла с таким номером операции на Drive.

## Расписание и ограничения

Workflow запланирован на 17-ю минуту каждого часа по UTC. GitHub не обещает запуск точно в минуту расписания: возможна задержка, поэтому это не способ мгновенно реагировать на письмо. При необходимости измените строку cron в `.github/workflows/mail-to-drive.yml`.

GitHub Actions не является бессрочно бесплатным постоянным сервером: бесплатные минуты и доступность зависят от типа аккаунта и репозитория. Для одного короткого ежечасного запуска обычно расход небольшой, но следите за разделом Billing в GitHub. Если нужен запуск почти сразу или гарантии без задержек, понадобится постоянно работающий сервер либо иной облачный сервис.

## Безопасность

Репозиторий должен быть приватным. Никогда не добавляйте `.env`, пароль Яндекс Почты, JSON-ключ сервисного аккаунта или выгруженные письма в git. При утрате ключа сервисного аккаунта отзовите его в Google Cloud Console и создайте новый; при утрате пароля приложения удалите его в настройках Яндекс ID и создайте новый.
